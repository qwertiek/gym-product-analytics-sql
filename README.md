# gym-product-analytics-sql — Моделирование БД и продуктовая SQL-аналитика

Проект представляет собой разработку реляционной базы данных PostgreSQL для фитнес-центра «ActiveLife» и набор аналитических SQL-запросов для расчета продуктовых и бизнес-метрик.

## Бизнес-контекст и задачи
Фитнес-центр сталкивался с проблемами неэффективного учёта: разрозненные данные о подписках, посещениях и расписании приведили к ошибкам в финансовой отчётности и потере контроля над оттоком клиентов.

**Цели проекта:**
1. Проектирование реляционной структуры данных (10 таблиц, связи 1:M и M:M).
2. Автоматизация проверки активности подписок и учета посещаемости.
3. Разработка SQL-скриптов для продуктовой аналитики (Retention, загрузка залов, рейтинги, финансовые показатели).


## Структура базы данных
База данных содержит 10 сущностей:
- `clients` — данные клиентов
- `subscriptions` — месячные абонементы и их статусы
- `trainers` & `specializations` — тренеры и их квалификация
- `halls` & `class_types` — залы и направления тренировок
- `schedule` — расписание занятий
- `visits` — факты посещений (связь M:M между клиентами и расписанием)
- `trainer_specializations` & `trainer_hall_access` — связующие таблицы доступа и квалификаций


## Продуктовая аналитика и SQL-запросы (`analytical_queries.sql`)

В проекте реализованы следующие аналитические сценарии:
1. **Occupancy Rate (Заполняемость групповых занятий):** расчёт % фактических участников от максимальной вместимости зала.
2. **Финансовые метрики (Оконные функции):** расчёт накопительной выручки (`SUM OVER`) и скользящего среднего стоимости купленных подписок.
3. **Вовлекаемость и риск оттока (Engagement & Retention Proxy):** сегментация пользователей на основе количества визитов по активной подписке и расчёт удельной стоимости визита (`Cost per Visit`).
4. **Ранжирование тренеров:** использование `DENSE_RANK()` для определения наиболее популярных инструкторов по количеству проведенных тренировок.
